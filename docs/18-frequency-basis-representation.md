# FRC18 — Frequency-Basis Representation

## 1. Objective

FRC18 investigates whether changing the numerical representation of file data affects the explicit relationships generated by Frequency Relationship Computing (FRC).

The experiment compares two representations of the same input data:

- **Direct Byte-to-Channel Mapping:** maps file bytes directly into eight numerical channels.
- **Frequency-Basis Representation:** applies an orthonormal 8-point Discrete Cosine Transform (DCT-II) to each complete frame.

Both representations are then subjected to the same explicit relationship expansion, allowing their resulting numerical relationships to be compared.

The purpose is to investigate how different representations affect relationship values, not to establish DCT as a required component of FRC.

## 2. Experimental Design

The experiment reads a file as raw bytes and divides the data into frames of eight bytes.

Each byte is converted into a numerical value using:

\[
A_i = \frac{2b_i}{255}-1
\]

Where:

- \(b_i\) is the original byte value (0–255).
- \(A_i\) is the resulting channel value (-1 to +1).

Two representation paths are then evaluated.

### Path A — Direct Byte-to-Channel Mapping

Each group of eight bytes is mapped directly into eight numerical channels.

No frequency transformation is applied.

### Path B — Frequency-Basis Representation

Each complete eight-channel frame is transformed using an orthonormal 8-point DCT-II.

This produces eight mathematical frequency-basis coefficients.

The DCT is a linear transformation that changes the coordinate basis of the representation. It does not introduce additional information into the original data.

The DCT coefficients are mathematical representation components, not physical frequencies or evidence of physical frequency interactions.

## 3. Relationship Expansion

Both representation paths use the same explicit relationship calculations.

The experiment calculates:

| Relationship order | Features per complete frame |
|---|---:|
| First order | 8 |
| Second order | 28 |
| Third order | 56 |
| Fourth order | 70 |
| **Total** | **162** |

These relationships are calculated through explicit numerical products.

The experiment does not use a classifier or hidden nonlinear learning.

Relationship expansion is a central part of the FRC architecture. It creates a more expressive representation by exposing relationships that are not directly available in the original individual channels.

The purpose is not to replace relationship expansion with a more complicated classifier. The intended architecture retains a relatively simple, strictly linear classifier.

\[
\hat{y}=w^Tx+b
\]

The representation supplies the additional expressive capability, while the classifier learns only linear weights.

This distinction is fundamental to FRC: improvements in classification capability are intended to come from the explicit relationship representation, rather than from increasing the complexity of the classifier.

## 6. Computational Considerations

Although the 8-point DCT produced a different numerical representation, it introduces additional computational work.

The transformation requires weighted calculations using cosine coefficients. Reconstruction also requires an inverse transformation.

Direct byte-to-channel mapping requires only simple arithmetic.

The DCT comparison therefore does not establish a computational advantage over direct mapping.

Since an important objective of the FRC investigation is to keep representation processing computationally economical, the DCT will remain a comparison technique rather than a required component of the FRC architecture.

This does not mean relationship expansion should be removed.

Relationship expansion serves a different purpose: it deliberately increases the expressiveness of the representation so that a simple linear classifier can operate on explicit higher-order relationships.

Future efficiency investigations should distinguish between:

- The computational cost of converting input data into channels.
- The computational cost of generating explicit relationships.
- The computational cost of the final linear classifier.

Reducing unnecessary processing should not undermine the representational capability being investigated.

## 7. Interpretation

FRC18 establishes three observations.

1. Direct byte mapping and DCT produce different numerical representations of the same input.
2. Applying identical relationship expansion to these representations produces different relationship-value distributions.
3. Both representations can reconstruct the original file exactly in this experiment.

The experiment does not establish that DCT improves classification, reduces computation, or provides a superior representation.

Only one sample file was evaluated, and no classifier was included in this experiment.

The results therefore demonstrate a difference in numerical representation and relationship distributions, not a difference in classification performance.

## 8. FRC Architectural Position

The intended FRC processing architecture remains:

**Original file bytes → Direct byte-to-channel mapping → Explicit relationship expansion → Simple linear classifier**

The key architectural principle is that the representation provides additional expressive capability while the classifier remains relatively simple and strictly linear.

FRC does not require increasingly complex classifiers to obtain greater expressive capability. Instead, it investigates whether explicitly calculated relationships within the representation allow the same simple linear classifier to solve increasingly complex tasks.

Relationship expansion therefore remains an essential part of the research.

The DCT experiment is retained as a comparison demonstrating how an alternative mathematical basis affects the resulting relationships. It is not adopted as a required processing stage.

## 9. Limitations

- Only one sample file was used.
- No classification tasks or classifier comparisons were performed.
- No computational performance benchmark was conducted.
- DCT and direct mapping were compared numerically, not evaluated for semantic understanding.
- The experiment used mathematical transformations, not physical frequency processing.
- Streaming and large-file processing were not evaluated.
- The results do not establish that either representation is universally more useful.

## 10. Conclusion

FRC18 demonstrates that the numerical basis used to represent data affects the explicit relationships produced by subsequent feature expansion.

The direct and DCT representations generated different relationship distributions while both preserved the original file exactly.

However, the DCT introduces additional computation and does not demonstrate a sufficient benefit to justify making it part of the intended FRC architecture.

The direct byte-to-channel approach therefore remains the preferred representation for the current investigation.

Importantly, this decision does not remove or diminish relationship expansion. Explicit pairwise and higher-order relationships remain central to FRC because they provide the expressive representation through which a simple linear classifier can extend its ability.

**FRC18 status: Completed.**

The experiment provides a comparison of direct and frequency-basis representations and establishes the basis for retaining direct mapping while continuing to investigate computational efficiency in the relationship-processing stage.
